# Cursor 2月利用状況を踏まえた次アクション

## 前提

- 2月アンケートでは、`既存機能の改修・リファクタリング`、`テスト（設計・実施）`、`新規実装` で特に高い工数削減効果が見られた
- 一方で、`レビュー`、`テスト`、`資料作成` は負担増回答も一定数あり、特に `レビュー` はばらつきが大きい
- 自由記述では、`Rules` / `Skills` / `Plan` モード活用や、既存資料を参照させる使い方が有効とされる一方、出力品質のばらつき、確認工数、コスト懸念が課題として挙がっている

## 次に取るべきアクション

### 1. 高効果ユースケースを標準化して横展開する

最も効果が高かった `改修・リファクタリング`、`新規実装`、`テスト` の使い方を、再利用できる形でテンプレート化する。

- まずは社内で成果が出ている依頼文を 3〜5 パターン集める
- `どの資料を添付するか`、`どこまで自動生成させるか`、`最後に何を人が確認するか` をセットで明文化する
- 「まずこれを試す」スターターガイドとして配布する

### 2. レビュー・テスト向けの共通 `Rules` / `Skills` を整備する

負担増が出やすい `レビュー` と `テストコード生成` は、個人差の大きい使い方を減らすために、共通ルールを先に整えるべき。

- レビュー観点、禁止事項、出力形式を固定した共通ルールを作る
- テストでは、前提条件、観点、カバレッジ期待値を渡すテンプレートを用意する
- 「AIに任せる範囲」と「人が必ず確認する範囲」を明示する

### 3. 要件定義・設計で効果が出る使い方を型化する

`要件定義・設計` は他領域より削減効果が安定していないため、活用の前提となるインプットを揃える必要がある。

- 要件・設計用に、参照させるべき資料の最小セットを定義する
- `先に不明点を質問させる`、`粗く出してから詰める` など、有効だった進め方を推奨フロー化する
- 設計レビューや論点整理など、効果が出やすい用途から利用を広げる

### 4. 生成物の確認工数を減らすためのチェックリストを作る

自由記述では、生成結果の裏取りや安全性確認の負担が大きな課題だったため、確認観点を標準化して再作業を減らす。

- コード、設計、資料ごとに最低限の確認チェックリストを作る
- 事実確認が必要な項目、手動確認が必要な項目、AI再依頼で直せる項目を分ける
- レビュー時にチェックリストを使う運用にして、品質のばらつきを抑える

### 5. コスト・運用ルールを簡潔に整理して利用障壁を下げる

コスト懸念や新規案件適用時の相談ニーズがあるため、安心して使える最低限の運用ルールを早めに整える。

- `使ってよい場面`、`機密情報の扱い`、`コストを意識すべきケース` を1枚にまとめる
- 新規案件適用時の相談窓口や判断フローを明確にする
- 「まずはここまでなら安全に使える」という運用ラインを示す

### 6. 環境・UI課題を改善バックログとして管理する

OOM、重さ、IDE差分、対応ファイル種別などは、活用定着を阻害するため、個別の不満で終わらせず改善テーマとして管理する。

- 課題を `頻度`、`影響度`、`回避策の有無` で棚卸しする
- すぐ避けられるものはFAQ化し、避けられないものは改善要望として集約する
- 次回アンケートで改善有無を追跡できるよう設問に反映する

## 優先度の高い着手順

1. `高効果ユースケースの横展開`
2. `レビュー・テスト向け共通Rules/Skills整備`
3. `確認チェックリスト作成`
4. `コスト・運用ルール整理`

上記4件を先に進めると、既に効果が出ている領域を拡大しつつ、負担増の主因である `使い方のばらつき` と `確認コスト` を同時に下げやすい。
